Toolkit 0.8.0
Styles Injected, Palette Single Sourced

This release moves stylesheet assembly out of the model and into a script, returns the palette to one source file, and brings the shipped CSS in line with the rules it asks every output to follow. The validator grows four checks to keep it that way.

AudienceToolkit Maintainers
ScopeBrand, UI Components, Both Skills
DateSeptember 2026

Summary

Less Copying, One Palette, Stricter Checks

Three structural changes and a set of consistency fixes. Nothing in the component vocabulary changed, so existing markup still renders; what changed is how a document gets its styles and how the toolkit polices its own values.

Assembly

Styles Are Injected, Not Typed

A new script fills a style marker in the document with the layer files, byte for byte, and replaces its own block on re-run. Both skills stop asking the model to read and paste stylesheets.

Palette

The Palette Has One Source Again

The slides stylesheet reads the token file instead of restating the ten hexes and the type ramp. The QA and validate scripts read the palette through one shared module.

Consistency

Shipped CSS Follows Its Own Rules

Off-ramp chart label sizes, small literal radii and white hex literals are gone. Body weight in the token file now matches what every theme already did.

Enforcement

The Validator Catches What Slipped

Raw pixel font sizes, off-token radii, short skill descriptions and any em dash now fail validation. The palette check reads three-digit hex and rgb() forms it previously missed.

Verification

What The Release Checks, And What It Does Not Record

The notes describe the checks that now exist and one worked example. They do not record a run of those checks against the release itself, so that run is listed under next steps rather than claimed here.

Covered

Assembly Round Trip

The example report was assembled by the script from a bare marker, which exercises the fill path. Re-running replaces the block rather than appending, so the same document can be assembled twice without growing.

Covered

Closing Tag Guard

The script refuses a layer file containing a closing style tag. Without the guard a comment in any layer could end the style block early and unstyle the rest of the page.

Covered

Palette And Type Checks

The palette check now matches three-digit hex and rgb() and rgba() values, and check 6 scans the skills folder as well. Raw px font sizes and off-token radii fail, which is what caught the six label sizes and the literal radii.

Covered

Prose Checks

Skill descriptions under 80 characters fail, as does any em dash in docs, comments or snippets. Both rules were applied to the existing text in this release.

Not In The Notes

No validate.py or qa.py run against 0.8.0 is recorded, and no browser or print check of the assembled example is mentioned. Treat both as open until a maintainer confirms them.

Next Steps

Adopt The Script, Confirm The Checks

Four follow-ups for maintainers. The first two close the verification gap above; the other two carry the release's changes into documents and rules that still predate it.

1
Run The Validator Against The Release
Run validate.py and qa.py on the 0.8.0 tree and record the result. The new checks are strict enough to fail on files the release did not touch, so the first run is the baseline.
2
Open And Print The Assembled Example
Check the example report in a browser and as a PDF. It is the only document assembled by the script so far, and it is the evidence that the marker approach produces the same page the pasted approach did.
3
Re-assemble Older Examples
Earlier outputs still carry pasted CSS. Replacing their style block with a marker and running the script brings them onto the same layer files, and any drift shows up as a diff.
4
Settle The Body Weight Deviation
The token file now sets body in Regular, recorded as deviations section 9. Either the brand owner accepts Regular on screen or the themes move back to Light; until then the section stays open.

Where 0.8.0 Leaves The Toolkit

Styles come from the layer files through one script, the palette has one source, and the validator enforces the rules the shipped CSS now follows. The remaining work is confirmation, not construction.
