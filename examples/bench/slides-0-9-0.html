The Release In Three Numbers

What 0.8.0 Removed

90 KB
Of hand-copied CSS per output, now injected by script
26
White literals replaced with the palette token
4
New failing checks in the repo validator

The 90 KB is the argument: every byte of it was a chance for a document to drift.

The 90 KB figure is per generated document, not per repo, so it compounds with every report and deck we produce. The other two numbers are evidence that the rules now apply to our own shipped CSS.
Summary

Three Things Changed At Once

Style delivery, palette ownership, and what the validator allows.

  • Stylesheets are injected into a marker, never pasted
  • The palette is defined once and read by every script
  • Our shipped CSS passes the rules we publish
Land the first point hardest: it is the one that changes the model's job. The other two are cleanup that the first one made possible.

What Changed

Four slides here: the assemble pipeline, the before and after table, the palette source, and the CSS we fixed in our own files.
Assemble

How A Document Gets Its Styles Now

1
Mark
The document carries an empty style marker.
2
Fill
assemble.py writes the layer files in order, byte for byte.
3
Extend
Document rules go in a second style block after it.
4
Re-run
A second run replaces its own block, never appends.
Step four is the one people get wrong: after any edit to the document you re-run the script, and it is safe to do so as many times as you like. Step three is where every document-specific rule now belongs.

Our Own CSS

Shipped Styles Now Follow The Rules

Type

Six chart label sizes moved onto the ramp.

Shape

A new small radius token replaces every literal.

Weight

Body set in Regular, recorded as deviation nine.

The body weight was already Regular in every theme; 0.8.0 just wrote it down where the token lives and recorded the gap. The radius token is 4px, which the deck theme maps to 7.5 canvas units.
The Turning Point

A Rule We Do Not Enforce On Ourselves Is A Suggestion.

Every fix in this release started as a check that our own files would have failed.

Slow down here. This is the pivot from what changed to how we know it holds, and it is the framing to use for anything we add next.

Verification

Two slides: what the validator now catches, and the release document we produced with the toolkit itself as a live test.
validate.py

What The Validator Now Catches

  • Raw px font sizes
  • Off-token border radii
  • Skill descriptions under 80 characters
  • Any em dash, anywhere

Wider Palette Reading

The palette check now sees three-digit hex and rgb or rgba values, and check six covers the skills folder too.

The four failures on the left are new; the card on the right is existing checks widened. Expect the first run against an old branch to be noisy, mostly em dashes.
Evidence

The Release Documented Itself

The 0.8.0 write-up was produced with create-report and assembled from a bare marker.

Guard added: assemble.py refuses a layer file containing a closing style tag, which the browser would treat as the end of the block even inside a comment.
We found the closing tag problem by hitting it while writing this example, which is the argument for keeping a real document in the repo. Docs were also swept: stale version stamps, skill names in BRAND.md, and an edit order that 0.7.0 had inverted.

Next Steps

For Maintainers

What This Asks Of Us

Re-run, Do Not Paste

assemble.py after every document edit.

Keep Layers Clean

No closing style tag in a layer file.

Own The Second Block

Document rules go after the marker.

Clear The Backlog

Validate older branches before merging.

The fourth card is the only one with real cost, since the em dash and raw px checks will flag a lot on branches cut before 0.8.0. Ask for a volunteer to run it across open branches this week.
